# Reference architecture — source

The second paper, "The Secure Software Factory: A Reference Architecture", and what the
site renders from it.

- `software-factory.md` — the paper. Its prose and captions are the working group's final
  document, word for word, and the figures' alt text was added here; change the prose only
  to match a change the working group makes. `bin/build-pdf --paper software-factory`
  renders it to `/software-factory.pdf`.
- `figures/` — the paper's figures, generated by `figures/build-figures.py`. The PDF prints
  them all; `bin/sync-figure-partial` makes each a partial the page could inline, as it did
  Figures 3 to 5 before it drew the levels itself.
- `boundaries.yaml` — the four security boundaries as the page lists them, in the paper's
  words; the paper's figure of them, which the page links to; and the caption of the page's
  own drawing. That drawing is not one of the paper's figures: it is made by
  `bin/build-architecture-drawing.mjs`, into `layouts/partials/sf-architecture.svg` and
  `sf-architecture-narrow.svg`.
- `levels.yaml` — the three levels of autonomy as the page shows them, one at a time: the
  paper's name for each level, one plain sentence of the page's own saying who chooses the
  next step, and the paper's figure for the level with its caption. The page draws each
  level itself (`bin/build-levels-drawing.mjs`, into `layouts/partials/sf-level-N.svg` and
  `sf-level-N-narrow.svg`), on one skeleton with a box's name alone on the box and what it
  does in its tooltip, and the drawing links to the paper's figure. Rendered only while
  `params.softwareFactory.showLevels` is true.
- `contributors.yaml` — the authors, from the paper's byline. Nothing renders with
  `confirmed: false`.

Comments go in as issues through the software-factory form, which carries the
`software-factory` label.
