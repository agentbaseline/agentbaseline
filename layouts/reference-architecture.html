{{/* The page's own opening, not the homepage's line: what a factory is and what this architecture does about it. */}}

A software factory uses AI agents to turn a prompt, ticket or specification into tested code, and increasingly to deploy and operate it. This architecture keeps what an agent decides apart from what it may do: the agent proposes, policy authorizes, and infrastructure enforces.

Four boundaries

{{/* What the paper teaches first: the agent keeps its room to work, and what it can actually do is enforced outside its own decisions. */}}

An agent needs room to reason and try things. Four boundaries enforce what it can actually do, from outside its own decisions, whether it cooperates or not.

{{/* The paper's "A factory in action", cut to the moment that shows the separation, then the line that keeps tested code and the boundaries from reading as one thing (paper: the loops decide whether the software is acceptable, the boundaries what agents may do). */}}

Take an incident agent allowed to read one service’s logs for the last hour. If it decides it needs another service’s logs, the proxy blocks the request until a new authorization decision grants them. Tests are a separate check: code can pass every one and still come from an agent that reached too far.

Three levels of autonomy

{{/* The paper's claim, plainly: who decides the next step changes; the boundaries don't. */}}

The three levels differ in who chooses the next step: a developer, a predefined workflow, or an agent. The four boundaries stay the same. What grows is the share of supervision the infrastructure takes over from people.

Read the paper

{{/* Why to read the paper, not a list of its contents: it starts from what went wrong (Recent incidents: PocketOS; Hugging Face) and names the control each one was missing. */}}

The paper starts from real failures, like an agent that deleted a production database in nine seconds, and names the control each one lacked. It then shows what to build at each level, mapped to Agent Baseline’s controls.
