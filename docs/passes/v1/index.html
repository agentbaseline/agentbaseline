Security outcomes for enterprise AI agents

Draft for public comment · v1.0-draft
PDF · controls.yaml · repository

An enterprise deploying an AI agent is not provisioning fixed-function software. It is provisioning a programmable actor: an end user can reprogram it at runtime in natural language, changing what it is asked to do and how it uses approved tools and data. Existing controls still matter, but they were not built for that combination of runtime programmability, access and autonomy.

This catalogue defines what an enterprise must achieve, by outcome rather than by product category. Each outcome carries controls with stable identifiers, written to be cited.

Open for public comment until 30 September 2026. Identifiers are not yet frozen — read VERSIONING before citing.

The six outcomes

  1. DiscoverDIS-01…07 Discover every agent and its dependencies.
  2. AuthorizeAUT-01…06 Bind identity, task, target and authority.
  3. ConstrainCON-01…07 Limit components, runtime, data and reach.
  4. ValidateVAL-01…05 Admit the system and verify outcomes.
  5. ObserveOBS-01…04 Correlate activity and prove what happened.
  6. RespondRES-01…04 Stop, revoke, quarantine and scope impact.

33 controls across six outcomes. The six are the minimum category test: a product may implement one or more, but end-to-end control requires all six through an integrated architecture. By this catalogue's own test, none of the organizations that convened it is a complete implementation.

How to cite

DIS-01 (agentbaseline.org, v1.0-draft)

Identifiers are bare and permanent — superseded, never renumbered, never reused. They carry no project name so that a rename, or a transfer to a community body, never breaks a citation you have already published.

Contributing

Read, comment, contribute. The most useful thing you can do is tell us where a control is wrong, unimplementable, or missing. Open an issue against a specific identifier.

Crosswalks to frameworks you already run — NIST AI RMF, ISO 42001, OWASP, CIS — are the contribution we most need from outside the group that drafted this. See CONTRIBUTING.

Provenance

This work was convened by companies that sell products in the area it describes. Who they are, what they sell, and which outcomes they sell into is disclosed in PROVENANCE. Read it before you weigh anything here.
