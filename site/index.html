The Enterprise Control Plane for AI Agents

Working draft, v1.0 · July 30, 2026 · single-page draft · PDF · controls.yaml

AI agents differ from other enterprise software in one property with broad security consequences: their behavior is not fully defined before deployment. An end user can re-program an agent at runtime, in natural language, changing what it does and how it uses tools and data. Agents hold credentials, call tools, and act at machine speed against systems of record.

This document defines the six security outcomes an enterprise must achieve to operate such agents — Discover, Authorize, Constrain, Validate, Observe, Respond — and a control catalogue for each. It is written for security engineers, platform engineers, and architects. It extends existing identity providers, policy engines, and SIEM platforms rather than replacing them, and it deliberately does not prescribe how a model reasons — only the conditions under which an agent and each of its material actions may proceed.

Status: working draft, open for public comment until ⟡ September 30, 2026, in the repository. It is not a standard; no conformance program exists. Control identifiers freeze at v1.0 and are then stable: superseded, never renumbered. Contributors from Keycard, Docker, and Snyk wrote this draft; every section accepts co-authors by pull request, with the same standing as the original authors.

The six outcomes

  1. Discover DIS-01…07 Every agent and its dependencies, in an authoritative inventory reconciled against observed code, cloud, endpoint, identity, and runtime evidence.
  2. Authorize AUT-01…06 Attributable identity and purpose-, task-, resource-, and time-bound delegated authority for every consequential action.
  3. Constrain CON-01…07 Runtime, tools, data, and permissible actions bounded to the task in front of the agent.
  4. Validate VAL-01…07 Composition, behavior, and outcomes checked at admission and continuously after.
  5. Observe OBS-01…06 Correlated telemetry joining intent, actor, task, policy decision, action, target, and outcome.
  6. Respond RES-01…04 Stop, revocation, quarantine, evidence preservation, and impact scoping for unsafe activity.

The outcomes are distributed across identity, runtime, data, and observability boundaries; no single enforcement point delivers all six. They can be read as evaluation criteria for any control-plane implementation, commercial or internal.

Contributing

  • Comment on the draft — file an issue against any section; open issues are labeled, including good first issues.
  • Framework crosswalks — mappings to NIST AI RMF, OWASP, CSA MAESTRO, and ISO/IEC 42001; one is complete, the template covers the rest.
  • Control test methods — evidence examples and test procedures, control by control.
  • Co-author a section — by pull request; see GOVERNANCE.md for authorship and review.
